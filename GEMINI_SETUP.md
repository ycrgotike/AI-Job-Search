# Gemini application drafting

The dashboard Generate action and `tools/generate_application.py` use Gemini when explicitly enabled. The same key used by another project can be used here; Google project quota and billing are shared. API keys never belong in the browser or source code.

## Enable locally

Edit `.env` in this project root (already ignored by Git):

```dotenv
APPLICATION_LLM_PROVIDER=gemini
GEMINI_API_KEY=YOUR_GEMINI_API_KEY
GEMINI_MODEL=gemini-3.8-flash
```

Replace the placeholder locally with your key. The model is configurable; use an available text model supporting structured output. Environment variables override the file. Restart the dashboard once after installing this code; subsequent `.env` changes are read on each generation. Select a saved job with its full description and click Generate as before. No extra Python dependency is required.

To explicitly use the previous local generator, set `APPLICATION_LLM_PROVIDER=rules`. Missing credentials, quota failures, timeouts or invalid output in Gemini mode produce an error, never an undisclosed fallback. No live API test has been performed without a configured key.

## Content and verification

Gemini reads the complete resolved posting, canonical candidate evidence and writing references. It selects existing experience bullets and projects, drafts summary alternatives, selects supported skills and writes role-specific letter prose. Local code escapes all text into the existing templates; Gemini cannot supply executable LaTeX. A second model call reviews claims against the evidence. Invalid drafts are revised at most twice. Each API attempt defaults to a 120-second timeout (configurable from 30 to 180 seconds with `GEMINI_REQUEST_TIMEOUT_SECONDS`). Temporary HTTP 500/502/503/504 and connection failures receive up to two retries, with 2/4-second backoff (numeric Retry-After is honored up to 30 seconds). Authentication and quota errors are not retried. See the tailoring-quality section below for the current planning and content-review bounds; each logical call has at most three transport attempts.

Existing mandatory limits remain: CV exactly two pages, summary exactly four rendered lines, cover letter 300–350 words and exactly one page. Compilation and text extraction checks still run. Drafts require final visual and factual review; model review cannot guarantee factual correctness or an interview. New job-description technologies do not become candidate experience automatically.

Generation metadata in `tailoring_review.json` and the API result records provider/model and reported gaps. Credentials are never included. Gemini receives candidate professional information, the job description and writing references, which can contain personal details; contact fields are removed from the dedicated profile payload, but this is not a full anonymization guarantee. Google project data-handling terms apply. Nothing is submitted to an employer.

API reference: https://ai.google.dev/api/generate-content
Structured output: https://ai.google.dev/gemini-api/docs/generate-content/structured-output

## Tailoring quality (generator 2.9.0)

The source-linked responsibility plan ranks projects before drafting and records employer timing and qualification uncertainties. Final review checks both factual claims and actual duty coverage, with quoted links from the posting to letter text saved in `tailoring_review.json`. Unrelated research interests, generic openings, invented skills and boilerplate summary padding trigger revision. Gaps remain review notes rather than automatically blocking generation. German requirements are compared explicitly with recorded B2. German `Stellennummer` identifiers appear in subjects. Gemini summary fitting tries reviewed alternatives without adding filler.

One planning call (at most one repair) precedes up to six draft/review rounds (each may include a separate factual audit), in addition to bounded transport retries. This may increase generation time. No existing applications are regenerated by this upgrade. Model-assisted coverage remains subject to human factual and visual review.

After two repair opportunities, non-factual reviewer recommendations remain visible in `generation.quality_warnings` rather than blocking a grounded draft indefinitely. Primary-duty quote coverage, factual audit, length and compilation checks remain mandatory. Reviewer recommendations are retained in full, not discarded by keyword filters.

## Reliability fixes (2.9.1)

Reviewers receive the application date and profile-derived availability explicitly. The factual audit reviews model-written content rather than challenging the fixed closing produced by trusted code. Future contribution statements are not prior-employment claims, and impact-from-day-one slogans are not hiring dates. Word-count repairs return only letter fields, preserving the CV.

Failure reports and the latest rejected draft are saved privately under `reports/generation_failures/` (already ignored by Git). The generation result returns `diagnostics_file`. Reports retain only named document fields, stage and error, not API keys or complete request payloads. HTTP 429 requires quota/rate-limit recovery; it is not repaired by rewriting the letter or retrying the review loop.

## Transport diagnostics (2.9.2)

`GEMINI_REQUEST_TIMEOUT_SECONDS=120` is the default; existing `.env` files need no change. This allows slower full-document responses more time than the former fixed 60 seconds. It does not fix provider outages or quotas. Reports distinguish response timeout, DNS lookup, certificate verification, interrupted response and other connection errors, with stage, attempts and elapsed time. Certificate errors fail immediately and never disable TLS verification. Exhausted transport attempts do not restart content repair.

Exact copies of the host-owned availability/closing sentences are removed from generated paragraphs before word counting and factual review, so confirmed logistics appear once and the substantive word budget stays meaningful.
